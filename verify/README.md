# verify/ — raw measurements in live Photoshop

Not documentation and not CI tests. These are **measurement logs**: exactly what was asked of Photoshop and
what it answered. They stay in the repo because `place.js` rests on these numbers, not on Adobe's
documentation (Adobe does not document batchPlay IDs at all).

Run on **Photoshop 27.5.0** (2026 / PHSP 27), macOS 25.5.0, 2026-08-11.

## How it was run

Through the AppleScript channel, with no user interaction:

```bash
osascript -e 'tell application "Adobe Photoshop 2026" to do javascript "String($.evalFile(new File(\"/path/probe6.jsx\")))"'
```

`do javascript` runs **ExtendScript**, not UXP. That is important and sufficient: `executeAction`
and `batchPlay` are two facades over one Action Manager, so the descriptor `{_obj:'transform',
width:{_unit:'percentUnit'}}` in batchPlay and `putUnitDouble(sID('width'), sID('percentUnit'))`
in ExtendScript go to one and the same call. What does **not** carry over is the `imaging` module
(ExtendScript does not have it); `../verify-assumptions.psjs` covers that.

The form `do javascript file (POSIX file … as alias)` returns error 8800 — hence `$.evalFile`.

Test PNGs are generated by `gen_test_pngs.js` with **our own** `../png.js` — also a check of
fixed-Huffman deflate against Photoshop's real decoder, not only against `zlib`:

```bash
node verify/gen_test_pngs.js /tmp/psverify
```

Every script creates its own documents and closes them without saving; user documents are not
touched (each report starts with the line "documents already open").

## What each file measured

| File | What it measured | The main result |
|---|---|---|
| `report.txt` | first broad run, 10 assumptions | `transform rect→quad` = **silent no-op**; `place` on CMYK/16-bit **does not convert**; `pHYs` works; our PNG is read |
| `probe2.txt` | 7 ways to move an SO | `resize(%,TOPLEFT)`+`translate` = EXACT; `nonAffineTransform` is present **always** |
| `probe3.txt` | searching for a descriptor without the DOM | `transform QCSAverage + width/height %` = EXACT; `distanceUnit` in `move` is **points**, not pixels |
| `probe4.txt` | a matrix of 13 cases, 6 color modes | 13/13 EXACT; a fractional shift is **not** supported |
| `probe5.txt` | `move` with `pixelsUnit`; a mask from an alpha channel | both correct; the mask in CMYK 16-bit clipped `layer.bounds` exactly to the selection |
| `probe6.txt` | **the algorithm that is actually in `place.js`** | **14/14 EXACT, one pass, no document was converted** |

`probe6` is the only one that is a literal port of steps 4–5 of `place.js`. The rest is the scouting that led
to it. If `place.js` changes, `probe6.jsx` has to be rewritten and run again.

## How to rerun

```bash
node ~/ai-image-ps/verify/gen_test_pngs.js /private/tmp/psverify
```

Then adjust the `DIR` constant in the `.jsx` you need and run the `osascript` line above.
Photoshop has to be running; `pgrep -x "Adobe Photoshop 2026"` shows that.
